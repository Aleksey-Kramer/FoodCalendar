# Календарь еды

Локальный сайт для офиса: календарь, где на каждый рабочий день назначается ресторан, из которого заказываем еду.
Blazor Web App (.NET 8, InteractiveServer) + SQLite (Microsoft.Data.Sqlite + Dapper). Без авторизации: редактировать может любой в локальной сети.

## Запуск

Нужен только .NET 8 SDK.

```bash
dotnet run
```

Приложение слушает `http://0.0.0.0:8000`, то есть доступно с любого устройства в сети по адресу
`http://<IP-компьютера>:8000`. Порт задаётся в `appsettings.json`:

```json
"Kestrel": { "Endpoints": { "Http": { "Url": "http://0.0.0.0:8000" } } }
```

При первом старте создаётся БД со схемой и начальные данные: 11 ресторанов (Oshi Amiri, Evos, Burger King, Mazzali, Плов, PastaPasta, Ris, Yapona Mama, KFC, Bon!, Safia) с PNG-логотипами из `Data/SeedImages` (копируются в папку картинок под читаемыми именами: `oshi-amiri.png`, `plov.png` и т.д.)
и случайные назначения на все рабочие дни текущего месяца. Повторный старт данные не трогает.

## Где лежат данные

Пути задаются в `appsettings.json`, секция `Storage`:

```json
"Storage": {
  "DbPath": "storage/foodcalendar.db",
  "ImagesPath": "storage/images",
  "ReceiptsPath": "storage/receipts"
}
```

Относительные пути считаются от корня приложения: при `dotnet run` это папка проекта, у опубликованного
приложения — папка, из которой его запустили. Можно указать абсолютные пути. Папки создаются автоматически.

| Что | Где по умолчанию |
|---|---|
| База SQLite | `storage/foodcalendar.db` (плюс служебные `-wal`, `-shm`) |
| Картинки ресторанов | `storage/images/`: сиды под читаемыми именами, загруженные через сайт под GUID-именами |
| Чеки | `storage/receipts/<guid>.jpg|png|webp|pdf` |

Чтобы начать с чистой базы, остановите приложение и удалите папку `storage`.

## Структура проекта

```

```

## Открыть порт в брандмауэре

По умолчанию порт 8000. Если поменяли порт в `appsettings.json`, подставьте свой.

**Windows** (PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "FoodCalendar" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

или через `netsh`:

```cmd
netsh advfirewall firewall add rule name="FoodCalendar" dir=in action=allow protocol=TCP localport=8000
```

**Linux**, ufw (Ubuntu/Debian):

```bash
sudo ufw allow 8000/tcp
```

**Linux**, firewalld (Fedora/RHEL/CentOS):

```bash
sudo firewall-cmd --permanent --add-port=8000/tcp
sudo firewall-cmd --reload
```

## Публикация в один исполняемый файл

Windows x64:

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

Linux x64:

```bash
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

`IncludeNativeLibrariesForSelfExtract` нужен, чтобы нативная библиотека SQLite (`e_sqlite3`) попала внутрь файла.
В папке `publish` будут `FoodCalendar.exe` (или `FoodCalendar` на Linux), `appsettings.json` и папка `wwwroot`.
Скопируйте всё это на целевую машину (рантайм .NET там не нужен) и запускайте из этой папки:

```bash
cd publish
./FoodCalendar        # Windows: .\FoodCalendar.exe
```

Папка `storage` с базой и картинками появится рядом, в текущей рабочей директории. Если запускаете как службу
или из другой директории, пропишите в `appsettings.json` абсолютные пути `Storage:DbPath` и `Storage:ImagesPath`.

## Что умеет

- Календарь по месяцам (Пн–Вс), «Сегодня», подсветка текущего дня. Суббота и воскресенье недоступны;
  запрет продублирован в сервисе.
- Клик по рабочему дню: быстрый выбор основного ресторана, смена или очистка. Прошлые дни редактируются.
  Если у основного блюда заполнен чек, то «Убрать»/«Очистить» не удаляет его: чек скрывается и возвращается,
  как только для дня снова выбран ресторан (в том числе по итогам голосования). Пустое основное удаляется совсем.
- Страница дня (`/day/ГГГГ-ММ-ДД`, ссылка «Детали дня» из диалога): основное блюдо, дополнительные приёмы с меткой
  (завтрак, перекус, кофе или своя), для каждого приёма чек (картинка или PDF до 10 МБ), итог по чеку, участники
  (от руки или из списка людей, галочка «сохранить в список»), позиции участников (от руки или из меню ресторана,
  галочка «в меню» сохраняет позицию с ценой за рестораном), суммы по участникам и разница с чеком.
  Если имя или позиция уже есть в списке, галочка не показывается — ничего не дублируется. Итог по чеку
  сохраняется кнопкой «Сохранить» (и при уходе из поля). В формах чека стрелки ← → переключают поля.
  Суммы вводятся с разделением разрядов (30 000), дробная часть через запятую или точку.
  В календаре у дня показываются бейджи «+N» (дополнительные приёмы) и 🧾 (есть чек).
- Подсказка с чеком: при наведении на день с заполненным чеком рядом с ячейкой появляется чек основного блюда —
  ресторан, позиции, участники с их «Итого» и общая сумма. Ниже перечислены дополнительные приёмы: наведение на
  приём с чеком сворачивает основной и разворачивает его; у приёма без чека показывается «Чека нет».
  Работает только с мышью (на сенсорных экранах подсказок нет).
- Общие позиции чека (соус, упаковка, пакет) тоже подсказываются из меню ресторана и с галочкой «в меню»
  сохраняются в него с ценой за штуку; сборы «Доставка», «Работа сервиса» в меню не попадают. Всё это делится поровну на всех участников
  или только на выбранных. У каждого участника видно «своё + общее» и итог.
- Голосование (под календарём на главной): участник вводит имя (запоминается в браузере), выбирает день — сегодня
  или любой будущий рабочий день (в прошлое и на выходные нельзя), отмечает минимум два ресторана и начинает
  голосование. Голосования на разные даты идут параллельно, каждое в своей карточке; открытое голосование на
  прошедшую дату отменяется автоматически. Остальные видят его, отмечают свои варианты, могут добавить рестораны,
  нажимают «Голосовать», затем «Завершить голосование». Показывается «Проголосовало n человек». Итог подводится, только
  когда завершили все участники: победитель попадает в календарь как основное блюдо; при ничьей начинается новый раунд
  только с ничейными вариантами и без прежних голосов. Голосование можно отменить. Обновления приходят всем открытым
  страницам сразу, без перезагрузки.
- Рестораны: кнопка «Меню» со списком позиций и цен; они подставляются как подсказки при вводе.
- Люди: справочник участников для быстрого выбора.
- Рестораны: добавление, переименование, картинка (выбор файла, перетаскивание в форму или Ctrl+V из буфера; JPG/PNG/WebP/SVG до 2 МБ, тип проверяется по сигнатуре файла, SVG со скриптами отклоняется,
  файл сохраняется под GUID-именем), деактивация (soft delete) и восстановление.
- Нет картинки: плейсхолдер с инициалами на цветном фоне.

## Ограничения

- Авторизации нет: осознанно, для локальной сети.
- Праздники не учитываются, только суббота и воскресенье.
